# kmr Constitution

## Core Principles

<!-- ov-policy -->
### 0. ov Policy (NON-NEGOTIABLE)

- Paths listed in `.aiignore` are read-only for agents. Agents may read them and MUST NOT change
  them by any means, Bash included. A task that needs such a change stops and asks the human.
- `docs/srs/SRS.md` is written by humans only. `docs/srs/modules/*.md` are generated by
  `/speckit-ov-srs` and never edited by hand.
- Every agent commit carries an agent trailer (`Co-Authored-By: Claude <noreply@anthropic.com>`
  or `Assisted-by: claude-code`) and never removes it. A commit without one is a human commit.
  The trailer is how CI tells agent work apart; it is disclosure, and the human stays
  accountable for every line.
- Files written by ov setup commands (`.aiignore`, ov workflows, ruleset) are committed by a
  human.
- Work reaches `main` only through a pull request whose required checks pass. An agent never
  approves or merges a pull request.

Rationale: ov enforces these rules through the guard hook and CI, not prose. The trailer rule
supersedes any project text that forbids agent trailers.

### I. The SRS Is the Authority

- `docs/srs/SRS.md` decides. Specs, plans, code, docs and the C4 model follow it; on conflict
  the SRS wins and the conflict is reported.
- An open SRS question never blocks work: the exact path is marked
  `unimplemented!("SRS <id>: <question>")`, or `compile_error!` when a wrong guess is costly,
  and work continues. Markers are counted by CI; one left on the control path blocks a release.
- The delivery order of SRS section 8 is followed top to bottom.

### II. Real-Time Hot Path

- The control path has no heap allocation, no `dyn` and no lock. Controllers are dispatched
  statically. A signal check costs one atomic load.
- `kmr_core` is `std` by default and builds `no_std` without `alloc` behind an opt-in feature;
  CI builds that feature for one bare-metal target.
- Heap types are banned workspace-wide by the root `clippy.toml`; only `kmr_api` may use them,
  and never inside a tick.

Rationale: NFR-1, NFR-7, NFR-10. A missed deadline moves a motor wrong.

### III. No Panics, Errors Returned

- The engine contains no `unwrap`, `panic` or unchecked indexing, except the SRS markers of
  Principle I.
- A bad descriptor is a compile error, a bad dt or registration is a `run()` error, a bad port
  binding is a bring-up error. Errors are human-readable; release builds hide internal causes.
- No fault is silent: every fault sets a typed flag (FR-13.4).

### IV. Hand-Engineered Core, Small Surface

- `kmr_core` is hand-engineered and listed in `.aiignore`. Its invariants (field sealing,
  signal ordering, schedule type machinery, any `unsafe`) are explained, not edited, by agents.
- `pub(crate)` by default. State fields are sealed; `kmr_api` re-exports core types unchanged
  and holds all ergonomics. Controllers depend on `kmr_api` only.
- YAGNI: no speculative generality. Extension points stay compile-time (traits and generics,
  never trait objects).

### V. Measured, Not Guessed

- Performance claims are measured on the NFR-1 reference bench (Raspberry Pi 4) with the NFR-8
  measurement set; engine overhead and compile time are tracked.
- Every design decision is defended in `docs/decisions/`, in priority order: real-time
  performance, quality, developer experience.

### VI. Secure by Default

- Every network path is authenticated and encrypted, default deny, debug and visualization
  feeds included. Identities and keys are per machine and never live in the descriptor or
  source.
- The hot path never does crypto: `kmr_api` authenticates before a `Desired` reaches the
  engine. Robot behavior on faults is the user's; the tooling for it is kmr's (FR-13).

## Technical Constraints

- Rust 2024 edition; one Cargo workspace; crates at the root map one-to-one to SRS modules.
- Targets: x86-64, aarch64 and armv7 Linux; cross-builds work without hardware attached.
- The core never imports a vendor SDK or a middleware; adapters implement the sealed HAL
  contract, Zenoh lives in `kmr_api` only.
- Scalars are `f32`; `f64` only with a written justification.
- `cargo fmt --check`, `cargo clippy --workspace --all-targets` and
  `cargo test --workspace` pass on every change.

## Development Workflow

- Commits follow Conventional Commits; branches follow Conventional Branch, except agentic work
  on `agent/<topic>` branches.
- Agentic work requires a maintainer's authorization recorded on the pull request, opens a PR
  into the human branch it came from, never into `main`, and carries the `agentic` label.
- Per feature: specify, clarify, plan, tasks, implement, converge, then update the module's C4
  (`/speckit-ov-c4-code`) before the PR.
- The human must be able to explain every line before merging.

## Governance

- This constitution supersedes other project guidance; `AGENTS.md` and `CONTRIBUTING.md` give
  runtime detail and must not contradict it.
- Amendments are made by a human through a pull request that states the change, the version
  bump and its rationale.
- Versioning: MAJOR for removed or redefined principles, MINOR for added or expanded ones, PATCH
  for wording.
- Every review checks compliance; a deviation is justified in the PR or rejected.
